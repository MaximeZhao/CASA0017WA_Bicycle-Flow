# 数据库检查与调整

## 原表的评价

原来的 bike_stations 对“每站点最新车辆数”是可用的，但不满足历史地图的需求：

1. 站点 ID 为唯一主键，采集时 ON DUPLICATE KEY UPDATE 覆盖之前观测。
2. 站点资料和时间变化的状态混在一张表。
3. 缺少空桩、容量、运营状态，前端无法获得还车信息。
4. 经度/纬度和车辆数缺少校验约束。
5. 建表脚本仅 USE 数据库，没有创建数据库的步骤。
6. Python 明文凭据；静态服务原来允许访问项目内任意文件，可能暴露源代码和凭据。

本次只调整代码和提供无破坏性的建表/迁移脚本，不直接清空或转换用户数据库。

## 新模型

```text
stations (station_id PK)
   1
   └── N station_snapshots (station_id + recorded_at PK)

collisions (collision_id PK，可独立为空)
```

站点名、位置、区域放 stations；数量、容量和运营状态放快照。NULL 表示未知。
日期查询使用 recorded_at 范围与索引，避免在 WHERE 对索引列套 DATE 函数。
每次采集或导入在一个事务中写入；失败回滚。相同主键重复导入保留原快照。
MySQL 8.0.16+ 执行 CHECK 约束；应用层也校验真实范围和数据类型。
所有 SQL 使用参数绑定；数据文件先校验再开启数据库写入。

## 时间语义

- 全部 DATETIME 明确约定为 UTC，前端也显示 UTC。
- recorded_at = 本项目采集时刻，不是源端所有字段更新时间。
- 每站点可有不同采样时间；时间轴取各站点在选定时刻之前的最近一条。
- 不用未来采样补过去，不插值编造整辆车。
- 缺少记录、过期、运营状态未知：灰色。
- 历史资料中的站点名称/位置使用当前 stations 值；若要分析站点搬迁，需要额外做资料版本表。

## 原数据迁移

schema.sql 不删除旧表。migrate-legacy.sql 只插入新表中不存在的记录。
先检查时区和无效数据，备份后执行；旧表没有的字段保持 NULL。
重复采集曾覆盖的数据不可恢复，只能从开始持续采集后累计历史。

## 真实 MySQL 验收

1. 新数据库执行 db:init。
2. 导入 example-station.json，得到 1 站点 + 13 快照。
3. 再导入相同文件，仍为 13 快照。
4. 增加新时间并导入，历史增加一条。
5. 将 DATA_SOURCE 设为 mysql，验证 /api/dashboard 与页面。
6. 停止数据库，接口报错且页面不伪装为演示数据。
